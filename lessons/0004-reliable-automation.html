Lesson 4 · 约 15 分钟

正确结束、取消和恢复

可靠自动化的核心不是启动命令，而是识别唯一终态并处理不确定副作用。

本课成果：你能设置 timeout、解释 Ctrl-C、按 Machine Error Code 分支，并安全卸载。

1. Timeout 与 max-turns

jiaorong-cli \
  -p '执行任务' \
  --model MODEL_ID \
  --output-format stream-json \
  --timeout 300 \
  --max-turns 1

Timeout 走真实远端取消路径。--max-turns 1 只表达 Headless Run turn；它不能限制 JiaorongAI 内部工具循环。

2. Ctrl-C

第一次 Ctrl-C 请求远端停止并等待最多 30 秒。第二次会强制本地退出；若因此没有 result，只能记为协议失败，不能声称远端已取消。

3. 按机器码处理

INVALID_ARGUMENT / PERMISSION_DENIED修正输入或权限，不原样重试
MODEL_UNAVAILABLE刷新模型目录后退避或换 available ID
TIMEOUT / INTERNAL_ERROR先检查可能副作用；安全时最多谨慎重试
CANCELLED记录取消，不当成成功

4. JSONL 消费契约

  1. 逐行解析 stdout。
  2. 要求 init 第一且唯一。
  3. 配对 toolCallId。
  4. 等待 result 最后且唯一。
  5. 对照 status、error.code 和 exit。
  6. stderr 单独存储。

5. 卸载

npm uninstall --global @jiaorong/cli
command -v jiaorong-cli

卸载不会删除 JiaorongAI.app、账号、Provider 或 Agent Session。

练习

  1. 运行一个带 60 秒 timeout 的 stream-json 短任务。
  2. 写下可靠成功的四个条件。
  3. 解释如果第二次 Ctrl-C 后没有 result，调用方应该记录什么。
  4. 在速查表中找到 exit 42 和 130 的含义。
自测：TIMEOUT 后能否直接重跑写文件任务？

不能先假定无副作用。先检查文件实际状态，只有操作可安全重复时才重试。

权威来源：错误与退出码、SIGINT 取消
