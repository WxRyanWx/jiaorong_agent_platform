# 应用中心（App Center）

## 用户需求

1. 主窗口侧栏在协同平台图标下方新增「应用中心」入口。
2. 应用中心可见性由 OSS 运行时配置（`jiaorong-runtime-config.json`）顶层新增数组控制，
   匹配机制与管理员一致：本地 `userInfo` 的手机号或 userName 命中即可见。
3. 配置新增开发者手机号数组；开发者额外能力：
   - 同样可进入应用中心；
   - 能看到单应用 `auth` 未通过的启用应用（上线前自测）；
   - 可卸载已装应用。
4. 配置 `apps` 中除 `collaboration-platform` 外的应用一律走远程 zip 下载 / 安装 / 更新，
   且只出现在应用中心，不再出现在侧栏。
5. `collaboration-platform` 逻辑不变：内置目录、侧栏显示。
6. 本地配置样例补字段（名单留空），负责人补名单后手动上传 OSS。

## 目标

- 侧栏入口 + 路由页 `/app-center`，卡片风格参考技能市场：图标 / 名称 / 描述 / 提供方 / 操作按钮。
- 卡片不展示「已安装」状态文案：有「打开」按钮即代表已安装；原状态位展示配置 `provider` 字段（提供方），缺省留空；仅安装失败时该位红字提示。
- 「有更新」判定为 semver 比较：仅目录版本新于已装版本才显示更新按钮。
- 主进程提供应用中心列表、安装（下载 zip + 可选 sha256 校验 + 解压安装）、卸载 IPC。
- 配置解析支持 `appCenterVisiblePhones` / `developerPhones`。

## 验收标准

- 非白名单用户侧栏无应用中心入口，直连路由页时列表为空态不影响宿主。
- 白名单用户可见入口；OSS 配置到达前入口隐藏，到达后响应式出现。
- 开发者可见 auth 未通过的启用应用与卸载按钮；普通白名单用户不可见。
- 远程 zip 应用：未装显示「安装」，版本不一致显示「更新」，已装显示「打开」；
  下载失败 / 校验失败返回错误且不污染用户 apps 目录。
- 协同平台侧栏行为与内置安装逻辑零变化。

## 约束

- 改动尽量收敛在 `src/jiaorong_src`；侧栏仅加一个按钮块。
- 用户可见文案走 i18n（zh-CN 为源，全 locale 补齐）。
- 复用现有 appsManages 安装 / 卸载能力，不新造安装器。

## 非目标

- 不做应用上传 / 发布后台。
- 不做下载进度条（按钮级 installing 态）。
- 不改 guest 桥、协议隔离与会话归属逻辑。

## 开放问题（已决）

- 开发者数组用途：按上述「额外能力」落地；若后续产品调整，仅改 `appCenter.ts` 选择函数。
- 远程包形态：`package.kind = "zip"` + `downloadUrl`（OSS 同域 `xkprosdk/jiaorong-apps/<id>.zip`），
  `sha256` 可选，提供则校验。
- 安装完成后「打开」复用现有 `jiaorong-app` 路由与 webview 宿主。
