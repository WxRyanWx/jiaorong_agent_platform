# 开放平台发布弹窗（spec）

## 背景

开发者中心的技能 / 连接器卡片当前把「版本号」「发布组织」两个必填输入框直接铺在卡片
footer 上，字段拥挤且与应用（AppsPane）的弹窗发布交互不一致。用户反馈版本号字段
位置混乱，要求把发布改成弹窗交互。

## 用户需求

1. 技能 / 连接器的「发布」「更新」改成一个弹窗完成，弹窗内展示只读详情（不允许修改）。
2. 技能必填：发布组织、版本号、技能类型（下拉选择框）。
3. 技能类型数据走 `deepchat-ext/skillCategory/list`，选中后把 `id` 赋给 `categoryId`
   随发布接口提交。
4. 连接器弹窗：只读详情 + 发布组织 + 版本号（无技能类型）。
5. 卡片上不再放版本号 / 发布组织输入框。
6. （第二轮）更新技能 / 更新连接器复用同一弹窗：点「更新」直接开弹窗，弹窗内新增
   必填的 zip 包选择项；选包解析成功后只读详情切换为包内信息。
7. （第二轮）弹窗底部「确认发布 / 确认更新」必须走二次确认气泡（ConfirmAction），
   校验通过才弹出气泡，与应用发布弹窗一致。

## 目标

- AssetPane 发布 / 更新链路收敛到弹窗，交互与 AppsPane 对齐。
- `OpenPlatformClient` 契约新增 `listSkillCategories()`，http / mock 双实现。
- 技能发布（`assets/publish`）表单新增 `categoryId` 字段（仅技能，连接器不送）。

## 验收标准

- 草稿卡片点「发布」→ 弹窗展示只读详情 + 版本号 / 发布组织 /（技能）类型下拉，
  确认后完成发布；缺 zip 时先弹文件选择器，选完自动继续提交。
- 已发布卡片点「更新」→ 先选 zip，解析成功后弹窗（详情取包内信息），确认后完成更新。
- 技能未选类型 / 版本号为空或格式错误 / 版本未递增 / 发布组织为空时，弹窗内报错且不发请求。
- 技能发布请求表单携带非空 `categoryId`；连接器发布请求不携带。
- 「重新发布」（下架恢复）与「下架」「移除」保持 ConfirmAction 交互不变；
  重新发布门槛改读 `item.provider`（后端补 provider 字段后自动解锁）。
- mock 与 http 客户端都实现 `listSkillCategories`，mock 返回内置 5 条分类。

## 约束

- 代码全部落在 `src/jiaorong_src` 私有目录；不新增主仓触点。
- 复用既有 i18n 键（openPlatformPublishVersion / Organization 系列），
  新增文案沿用本文件既有硬编码中文风格（AssetPane 既有大量中文硬编码）。
- 分类下拉数据只可硬编码进 mock，不得写进业务逻辑。

## 非目标

- 不改「重新发布」为弹窗（沿用原版本号，仅需确认）。
- 不动应用（AppsPane）发布链路。
- 不做技能类型的多选 / 新增分类能力。
