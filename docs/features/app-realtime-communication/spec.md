# 子应用实时通信

## 需求

- 已打开的子应用 A 调用 `window.jiaorong.app.emit()`，向已打开的子应用 B 实时投递一条业务事件。
- B 通过 `jr.on('app.message')` 接收事件。
- 事件 `type` 为 `<来源应用id>:<业务type>`，来源前缀由主进程注入，A 不能伪造。
- 目标应用当前未打开时返回 `APP_NOT_READY`，不做离线暂存。
- 权限只校验当前用户是否可见目标应用，不增加应用间白名单。

## 验收

- A 向 B 发送事件后，B 收到 `type`、`data` 并可自行处理。
- C 应用发送同名业务 `type` 时，B 收到 `c-app:<type>`，不与 A 混淆。
- B 未打开时调用失败，不产生后台消息堆积。
- 目标不存在或当前用户不可见时返回 `APP_NOT_FOUND`。
- 参数非法或 JSON 序列化后超过 64KB 时返回 `VALIDATION_ERROR`。
- 同一目标应用在多个窗口打开时，所有已打开实例都会收到事件。
- 一期 `app.open`、一次性 `app.intent` 和既有桥行为不变。

## 非目标

- 不做请求 / 响应、ACK、重试、顺序保证和离线消息邮箱。
- 不做应用间白名单、内容审核或业务字段约束。
