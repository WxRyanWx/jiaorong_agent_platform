# 实现方案

1. 新增 `app.emit` 桥契约：校验目标、业务 type、JSON data 和大小，注入来源前缀。
2. 主进程只向当前已打开的目标 guest webContents 推送 `app.message`，不打开目标、不暂存。
3. guest preload 暴露 `jr.app.emit`，复用现有 `jr.on` 事件分发。
4. 增加主进程桥测试，覆盖成功、来源前缀、多实例投递、目标未打开、权限和非法参数。

## 安全边界

- 来源应用身份从当前调用方 runtime 推导。
- 目标应用必须是已登记、当前用户可见且已有 guest 页面。
- 业务 `type` 只允许小写字母、数字和中划线，保证来源前缀无歧义。
- `data` 必须是 JSON 对象，序列化后 UTF-8 不超过 64KB；不限制业务字段含义。
