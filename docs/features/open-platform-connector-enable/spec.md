# 开放平台连接器启用

## 用户需要

开发者在开放平台上传连接器 zip 并发布后，插件中心的连接器列表已经能看到该连接器卡片（例如 `jina-public-mcp`）。
用户拨动卡片开关时，需要真实启动这个 MCP 服务，启动后它的工具能在对话里被智能体调用。

当前拨动开关没有任何反应，详情面板的「编辑服务器」弹窗是空白的，连接器完全不可用。

## 目标

- 开放平台解析连接器 zip 时保留 `mcp.json` 里的完整 MCP 服务配置，不再只留 id、名称、简介、类型。
- 连接器市场列表按后端契约 `ConnectorMarketItem` 返回 `config`、`source`、`sourceId`。
- 插件中心连接器卡片把远端条目与本地 MCP 列表融合展示，未安装的连接器开关可点击。
- 拨动未安装连接器的开关时，把远端 `config` 落地为本地 MCP 服务器并启用，之后完全复用现有 MCP 链路。
- 已安装连接器的启用、停用、编辑、删除、诊断、工具面板行为与普通自定义 MCP 服务器一致。
- 启动后的工具进入 `visibleTools`，在对话里可被智能体调用。

## 验收标准

- 发布一个 `type: http` 且带 `url` 的连接器后，插件中心卡片开关可点击，拨动后状态变为运行中。
- 发布一个 `type: stdio` 且带 `command`/`args`/`env` 的连接器后，同样可以通过开关启动。
- 启动成功后卡片工具数大于 0，对话输入框的 MCP 工具列表里能看到该服务器的工具，并可被调用。
- 关闭开关仅停用服务，本地配置保留；再次拨动可重新启动。
- 已安装连接器的详情面板「编辑服务器」打开的是带真实配置的表单，不再是空白弹窗。
- 已安装连接器可以删除；删除后市场远端条目重新以未安装状态展示。
- 未安装连接器的详情面板不展示「编辑服务器」「删除服务器」。
- 开放平台连接器 id 与本地已有 MCP 服务器重名时，本地落地名称自动追加后缀，两张卡片不重复展示同一连接器。
- 旧 mock 数据（没有 `config`）不导致页面崩溃，卡片以不可启用状态展示。
- 后端接口接入后，只要返回符合 `ConnectorMarketItem` 的数据，启用链路无需改动。

## 约束

- 不修改现有 MCP 启动链路：`toggleServer`、`setMcpServerEnabled`、`startServer`、`serverManager`、`mcpClient` 全部保持原样。
- 远端 `config` 到本地 `MCPServerConfig` 的映射只允许存在一个适配函数，作为后端接入时唯一的拼接点。
- 不改变后端契约文档已定义的 `ConnectorMarketItem` 形状；mock 输出必须与契约一致。
- 密钥类字段（`customHeaders`、`env`）复用现有 MCP 表单的遮蔽与持久化逻辑，不新增展示策略。
- 全局 MCP 开关默认开启且用户无法关闭，启用逻辑不需要处理全局开关关闭的分支。
- 用户可见文案走 vue-i18n。

## 非目标

- 不实现远端下载、鉴权、版本比对或后端市场能力。
- 不实现连接器的自动更新与卸载语义（关闭开关只停用）。
- 不调整 ACP 智能体的 MCP 勾选逻辑，沿用现有行为。
- 不调整技能、交融应用、IM 的发布与安装逻辑。
- 不改动内置 MCP 市场（mcprouter）的安装链路。

## 关联目标

`docs/features/plugin-center-connector-copy/` 只做连接器文案调整，其非目标中记录的
「不实现开放平台连接器启用能力」由本目标实现，该历史目标的范围声明保持原样不改写。
