# 开放平台一期 Specification

状态：active
最后确认：2026-10-19

## 背景

当前客户端的「开发者中心」只支持交融应用本地登记、调试和 zip 发布。产品需要将其升级为「开放平台」，提供首页、交融应用、技能、连接器四个入口，并由服务端统一管理发布、更新、下架和可见内容。

正式需求与后端契约为：

- `/Users/wangzhaoyu/Downloads/开放平台需求与交互设计.md`
- `/Users/wangzhaoyu/Downloads/开放平台后端接口契约.md`

## 用户价值

- 交融应用创建者可以在客户端完成本地调试、发布、更新和下架，并在浏览器完成发布、更新和下架。
- 技能和连接器创建者可以上传 zip 直接发布，不需要审核流程。
- 所有登录用户可以在插件中心看到并使用已发布的交融应用、技能和连接器。
- 开放平台页面在一期嵌入客户端，二期可独立部署并切换线上地址，不重写业务代码。

## 功能范围

## 分期边界

### 一期：客户端内完整实现

- 交付开放平台四个 tab、交融应用、技能、连接器的发布 / 更新 / 下架闭环。
- 页面嵌入客户端现有路由，同时按可独立构建的闭环模块组织代码。
- 完成插件中心远程 MCP 合并、技能市场数据源同步和交融应用安装链路。

### 二期：独立部署切换

- 将一期闭环页面构建为独立 Vue 应用并部署到云端。
- 客户端入口从本地路由切换为线上地址嵌入。
- 补齐 SSO 登录态传递和 iframe / postMessage 白名单桥。
- 不新增业务功能，不改资产数据模型和接口契约。

二期仅作为一期架构约束和验收项，不纳入本次开发任务。

### 首页

- 首次进入默认展示首页。
- 首页仅展示占位，不出现假数据、假统计和不可点击入口。
- 用户切换 tab 后写入浏览器存储；后续进入恢复上次 tab。

### 交融应用

- 保留当前开发者中心的主交互：本地目录创建、打开调试版、生产 / 调试进程冲突处理、发布弹窗和版本更新。
- 未发布应用仍只存在客户端本地卡片，不调用后端，不上传本地目录。
- 发布成功后才创建服务端记录；客户端将 `scope=mine` 服务端记录与本地卡片按应用 ID 合并。
- 发布弹窗和脚手架不展示 `slot` 选择，前端提交时始终带 `slot`，默认 `app-center`；`slot` 解析与展示逻辑不变。
- 发布表单内触发的确认交互使用绑定在按钮上的 Arco Popconfirm，且不能被外层 Dialog 判定为外部点击。
- 开放平台操作按钮统一使用 Arco Button，避免 shadcn Button、原生 button 和 Arco Button 混用。
- 二次确认仅用于发布、更新、下架、移除等会修改数据或列表状态的操作；打开本地调试应用不二次确认。
- 发布表单提供 `auth` JSON 对象编辑器；归一化规则按 `AppAuth` 执行。
- 浏览器模式提供发布、更新、下架和移除草稿 / 已下架记录；本地目录选择、目录回显和打开调试版仅客户端可用。
- 后端统一使用 `GET /assets`、`POST /assets`、`POST /assets/{type}/{id}/actions` 三个接口；前端分模块 client 方法只是适配层，不作为后端接口拆分依据。

### 技能

- 选择 zip 后解析元信息并创建服务端草稿；发布和更新调用 `POST /assets`，`type=skill`、`mode=publish`。
- 技能 zip 根目录必须包含 `SKILL.md`，不允许多个技能。
- 技术 ID 为 `SKILL.md.name`，中文名为 `metadata.displayName`，简介为 `description`。
- 技能不做用户版本管理和版本递增校验。
- 插件中心技能市场沿用现有技能接口；后端发布、更新、下架时同步写入现有技能市场数据源。

### 连接器

- 连接器等同于当前插件中心 MCP。
- 一个 zip 只允许一个 MCP 服务；`mcp.json` 必须在 zip 根目录。
- 服务名同时作为技术 ID 和展示名，可直接使用中文。
- 服务端按 `MCPServerConfig` 映射生成 `scope=market` 配置；`stdio` 支持 `inheritEnv`，远程类型不生成。
- 插件中心按服务 ID 合并本地与远程 MCP；本地同 ID 优先。
- 用户点击启动时走客户端现有 MCP 启动流程。

## 验收标准

1. 开放平台入口名称显示为「开放平台」，四个 tab 与持久化行为符合需求文档。
2. 客户端交融应用的现有创建、打开、发布、更新、移除和冲突处理行为不回退。
3. 发布成功后交融应用服务端记录可见，客户端与浏览器刷新后均能回显状态和版本。
4. 更新时 ID 不可修改，同一记录新版本必须大于当前版本；版本允许小于 `1.0.0`。
5. 下架后 `scope=market` 不可见；创建者 `scope=mine` 仍可见并可更新重新上架。
6. 技能和连接器发布、更新、下架主流程可用，不做审核和版本递增。
7. 插件中心能查询并展示已发布技能 / MCP，且与本地列表合并不产生重复或错误覆盖。
8. 客户端安装链路能查询已发布交融应用，并按 `source` / `slot` 展示。
9. 开放平台业务代码位于闭环目录，不直接依赖 Electron preload、客户端路由和客户端全局 IPC。
10. 浏览器环境降级后不显示本地目录和打开调试版能力。

## 非目标

- 一期不做审核流和版本审批；技能、连接器支持服务端草稿，交融应用不做服务端草稿。
- 移除仅作用于交融应用本地卡片、技能 / 连接器草稿，或三类资产的已下架记录；发布中记录必须先下架。
- 一期不做云端独立部署、SSO 落地、iframe / postMessage 桥落地。
- 一期不做开放平台首页真实内容。
- 一期不做技能和 MCP 可见范围控制、版本管理。
- 一期不改变技能 / MCP 运行时执行能力，运行仍由客户端现有 runtime 负责。
- 一期不做病毒扫描、敏感字段拦截和内容审核。

## 约束

- 包结构、字段映射、版本比较和 `auth` 归一化以正式契约和当前客户端实现为准，不新增客户端没有的校验。
- 用户可见文案使用 i18n；不做多语言硬编码。
- 新目录使用小写加横线命名；Vue 使用 Composition API 和 `<script setup>`。
- 原生能力必须通过 capability adapter 注入，不直接读取 Electron API。
- 接口调用统一使用开放平台 API client，`API_BASE_URL` 和 token 由环境适配器提供。
- 保持现有开发者中心业务逻辑可迁移，不做两套交融应用实现。
