# 交融应用可见范围组织输入

状态：active
最后确认：2026-10-21

## 用户需求

- 交融应用发布和更新表单不再展示可见范围 JSON。
- 用户手动填写可见范围组织名称，例如“信科集团”。
- 空值保持现有语义：不限制可见范围，全员可见。
- `auth` 增加一个新字段 `orgNames`，保存用户输入的组织名称字符串。
- `auth.orgs` 继续只保存组织号数组，不承载组织名称。
- 后端读取 `auth.orgNames`，把真实组织号写入 `auth.orgs`。
- 客户端可见性判断继续只依赖 `auth.orgs`。
- 后端必须在返回市场数据前完成 `orgNames -> orgs` 映射；否则客户端会按现有空数组规则视为全员可见。

## 验收标准

1. 发布、更新、重新发布表单均只展示“可见范围组织”文本输入。
2. 用户输入多个组织名称时，可使用逗号、中文逗号、顿号或换行分隔，前端原样提交到 `auth.orgNames`。
3. 提交时 `auth.orgs` 保持空数组，`userIds` 和 `phones` 保持空数组。
4. 空输入提交 `auth=null`，继续表示全员可见。
5. 不再出现 JSON 编辑器、JSON 校验错误或 JSON 占位内容。
6. 服务端返回给客户端的市场数据中，`auth.orgs` 必须是已映射的组织号数组。

## 非目标

- 不做组织名称到组织号的自动映射。
- 不改变 `auth.orgs` 的数组语义。
- 不增加技能、连接器的可见范围配置。
