# 远端资产版本同步（spec）

## 背景与决策

原契约里技能与连接器 `version` 为 `null`，曾计划用发布指纹（sha256/updatedAt）比对。
需求方已拍板改为**显式版本号**方案：

- 开放平台发布技能/连接器时新增必填 `version` 参数（semver 三段式），
  UI 放在「提供组织」输入框左边；提交新制品时校验必须大于上一版本，
  下架后沿用原包重新上架时沿用原版本号。
- 插件中心的技能与连接器用版本号比对控制「更新」按钮，点击后重新加载新的技能包 / MCP 配置。
- 详情面板「最近同步时间」需要新增本地时间戳字段，按需求方要求本期不做。

### 版本号递增口径（业界对照）

业界把「发布新制品」与「恢复列表可见性」分开处理，本项目沿用同一口径：

- 提交新制品：版本号必须递增且不可复用旧号。npm `publish`、VS Code Marketplace、
  Chrome Web Store 都拒绝重复或更低的版本号，保证同一版本号只对应一份内容。
- 仅切换可见性（下架 / 重新上架）：沿用原版本号。JetBrains Marketplace 的
  hidden release 与 unhide version、Figma Community、Google Workspace Marketplace、
  Shopify listing 都不要求重新上架时抬版本。

本项目「下架」只翻转 `status`，保留 `version` / `config` / `packagePath`；
技能与连接器的「重新发布」不重选 zip，属于可见性开关，沿用原版本号；
应用中心的「重新发布」必须重选 zip，属于提交新制品，仍按递增校验。

## 目标

- 发布侧：技能与连接器发布（含更新、重新发布）必须携带合法版本号；
  提交新制品时严格递增，仅恢复可见性时沿用原版本号。
- 连接器：市场版本 > 本地已装版本时卡片显示「更新」，点击后复用既有
  `updateServer` 链路写入新配置；连接参数变化时主进程按
  `bindingHash → configGeneration` 既有机制自动重连，参数未变则不打扰。
- 技能：市场版本 > 本地已装版本时卡片显示「更新」，点击复用既有安装链路
  （`installSkillFromZipUrl`，自带同名覆盖确认）重新落地。
- mock 与真实后端契约一致：`version` 进入 `OpenPlatformAssetSummary` 既有字段，
  真实接口接入后判定逻辑不变。

## 用户可见行为

1. 开放平台卡片出现「版本号」必填输入框（在「提供组织」左边），发布/更新/重新发布
   时校验非空、semver 格式；更新（提交新 zip）要求大于当前版本，
   下架后重新上架默认沿用当前版本号，只拒绝降版本。
2. 插件中心连接器卡片：远端版本更高时显示「更新」按钮，点击后本地配置更新、
   收到一次成功通知；启用中的服务器若连接参数变化会自动重连。
3. 插件中心技能卡片：已安装且远端版本更高时显示「更新」按钮，点击后重新下载安装，
   同名冲突走既有覆盖确认弹窗。
4. 本地改过的凭据（`authorization`、OAuth token、凭据绑定）与 `enabled` 开关在
   连接器更新后保留。

## 验收标准

- [ ] 发布技能/连接器不带版本号或格式非法 → 报错，不发布。
- [ ] 已上架内容提交新制品时版本号 ≤ 当前版本 → `VERSION_NOT_INCREASED`；
      > 当前版本 → 成功。
- [ ] 下架后重新上架（不带新制品）沿用原版本号 → 成功；版本号低于原版本 →
      `VERSION_NOT_INCREASED`。下架后重新上传新包仍按递增校验。
- [ ] 首次发布（当前版本为 null）→ 任意合法版本可发布。
- [ ] 连接器市场版本更高 → 已装卡片显示「更新」；点击后本地 `sourceVersion` 与
      连接配置刷新，`enabled`/凭据保留；版本相同或更低不显示。
- [ ] 旧配置无 `sourceVersion` 且市场有版本 → 视为可更新（补写版本）。
- [ ] 技能已装且市场版本更高 → 卡片显示「更新」；安装成功后记录新版本。
- [ ] `remoteInstallMap` 旧字符串值可平滑读取，不丢已装映射。
- [ ] 远端下架 → 仍按既有逻辑移除（回归不破）；列表为空或拉取失败 → 不删不更。
- [ ] 单测覆盖：发布版本校验、连接器更新对账与字段保留、技能版本映射兼容。

## 约束

- 不改主进程：`updateMcpServer` 合并语义、`bindingHash` / `configGeneration`
  计算沿用现状；`sourceVersion` 作为透传字段随 config 落盘。
- 不新增网络请求：复用 `listConnectors('market')` 与技能列表的既有拉取。
- 新增本地字段必须是可选的，旧数据能平滑升级。
- 代码位置遵循 `docs/architecture/open-platform-boundary/` 边界约定：
  版本比较工具放 `src/jiaorong_src/api/openPlatform/version.ts`，
  市场映射与对账放 `src/jiaorong_src/plugins/market/`，
  store 接线在 `src/renderer/src/stores/mcp.ts`，
  本地字段在 `src/shared/types/mcp.ts`，一律不写进 `open-platform/`
  （发布表单 `AssetPane.vue` 属开放平台页面，版本号输入框在其中）。

## 非目标

- 不做版本回滚、多版本并存、灰度发布。
- 不做静默自动同步（更新一律由用户点击按钮触发）。
- 不做详情面板「最近同步时间」展示（需要新增本地时间戳字段，本期不做）。
- 不改应用中心的既有版本机制（应用发布本来就带版本号校验）。
- 不做技能包内容 diff，仅按版本号判断。
