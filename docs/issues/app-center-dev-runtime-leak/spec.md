# 插件中心把开发者工作区当已安装 / 换目录后打开旧代码（spec）

## 现象

1. 在开放平台创建并发布应用后，创建者本人的插件中心应用列表**未安装就显示「打开」**，
   点开跑的是本地关联目录的代码，而列表本应要求先安装生产包。
2. 发布后重新关联 / 修改本地代码再打开，看到的仍是旧（生产）版本；升级版本号也无效，
   换一个新的 appid 才能看到新代码。

## 根因

- 现象 1：市场卡合并本地安装状态走 `listAppCenterItemsByIds`，它有意「不过滤开发者中心
  登记项」；开发者工作区运行时（`resolveDevRuntime`）恒为 `installStatus: 'installed'`、
  `openable: true`，于是创建者的市场卡直接显示已安装可打开。
- 现象 2：`appsManages.startApp` 复用在跑进程时只探活（`canReuseSpawn`），不比对进程
  启动时的 cwd。同 appid 换目录（重新关联工作区 / 换包）后，旧 Node 进程继续服务旧代码，
  webview 端口不变，界面停留在旧版本；换 appid 等于换 spawnId 才会重新拉起。

两个现象共享同一背景（开发者工作区运行时与生产安装副本的边界不清），但修复点独立。

## 验收标准

- 创建者未安装生产包时，插件中心市场卡显示「安装」而非「打开」；
  安装生产包后正常显示「打开 / 更新」。
- 手丢包（非开发者登记的 local-debug）与已安装生产副本的状态合并不受影响。
- `startApp` 在同目录时仍复用在跑进程；打开目录变化时杀掉旧进程并按新目录重拉。

## 非目标

- 不改开发者中心调试窗口（openDevAppWindow）自身的 link 生命周期。
- 不改市场卡「更新」判定逻辑（remote-asset-version-sync 已覆盖）。
