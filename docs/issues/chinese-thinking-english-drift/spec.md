# 中文提问时思考过程仍大量英文

## 用户需求

用户用中文提问时，【思考过程】不应被英文技能/工具描述带偏成英文叙述。

## 根因（排查结论）

1. `defaultSystemPrompt` 已有「语言要求」，但约束偏软，且主要出现在文首。
2. 宿主运行时会追加英文 Skills 元数据提示（如 `Before replying, always scan available skills...`）及英文工具/技能描述；模型常把这类 schema 语言当成工作语言，推理过程跟成英文。
3. 工具名、JSON、报错原文保留英文是合理的；问题在于整句推理（The user wants... / Let me...）被切换。

## 验收标准

- 提示词明确：用户消息语言是思考/回答的唯一语言判定源；技能/MCP/工具 schema 为英文时亦不得切换
- 补充正反例（中文用户禁止的英文思考句）
- 文末增加语言约束复读，对抗后注入英文材料的近因效应
- 不改变工具调用、安全与身份规则语义

## 约束

- 优先改 `@jiaorong/prompts/defaultSystemPrompt.ts`
- 不在本轮大改宿主 `buildSkillsMetadataPrompt`（可记为后续优化）

## 非目标

- 不翻译全部工具/技能英文描述
- 不强制英文用户改用中文
