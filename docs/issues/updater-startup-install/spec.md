# Windows 更新改为「启动时安装」

## 问题

根因只有一个：Windows 上 `autoInstallOnAppQuit = true`，用户正常退出就触发「先卸载旧版、再装新版」的安装器（`installSection.nsh:33/52/66`）。用户在卸载/解压窗口里再双击图标，会从半删除的安装目录启动，表现为崩溃；新进程还会占住文件让安装失败。

因此**不需要启动守卫**：被替换的程序没法可靠守卫自己的替换过程。把安装时机从「退出」搬到「下次启动」，竞态就从根上消失。

## 目标

1. Windows 不再退出时安装；改为**下次启动、创建窗口之前**安装，静默安装（`/S --updated --force-run`），装完自动拉起。
2. 启动安装**不走网络**：直接用上本地下载好的安装包（标记里记录路径），离线可用。
3. 下载完成后不安装、不打断；等下次启动。
4. 安装失败可重试，3 次后引导手动下载；缓存包 7 天过期；安装中再次启动不重复安装。

## 验收

1. Windows 退出时不出现安装器；下次启动在**创建任何窗口之前**判断，命中即静默安装并自动拉起，用户不会先进入界面。
2. 安装前弹**系统通知**「正在安装更新，完成后会自动重启」，无需点击；通知失败不影响更新。
3. 安装包不存在 / 超过 7 天 / 版本已追平 → 清标记，正常启动，不影响使用。
4. 上次安装失败（`installing` 且安装器不在）→ 本次启动重试；累计 3 次后进入手动下载态，不再自动安装。
5. 安装中用户再次启动 → `tasklist` 检测到安装器存活，直接退出，不重复拉起安装。
6. 用户手动装到比标记更新的版本 → 标记按 semver 清理，不会卡在错误态。
7. 关于页：平台信息到位后才显示下载链接；另有一个常驻的「手动下载安装包」入口；安装失败与检查失败文案分开。
8. macOS / Linux 行为不变。
9. 启动安装前校验安装包路径（必须在更新缓存目录内且为 `.exe`）与 `sha512`；不通过就清标记重新下载。
10. 直接拉起失败（权限/异常）时回退 `attempts` 并正常启动，不能空耗次数，也不能让客户端起不来。

## 非目标

- 不改安装包类型（仍是 assisted NSIS）。
- 不改发布产物名与 CDN（单独排查）。
- 不新增 i18n key（只有中文用户，文案直接写中文）。
